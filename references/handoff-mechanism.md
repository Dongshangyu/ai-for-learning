# 长期任务交接机制（Handoff）

用于跨对话的长期学习任务。用户的学习周期可能超过一次对话，必须把关键状态保存为 `handoff.md`，让下一段对话无缝接替。

## 文件规范

- 默认任务根目录：`C:\Users\19935\Documents\Codex\learning-tasks\<任务名>\`（示例/默认路径）
- 执行前先检查该路径是否对用户可用；如果用户没有这个目录，或用户另有偏好，先询问用户意见，商讨确定文件放置位置。
- 流程目录确认后，先创建任务根目录，后续笔记、论文、代码统一存放在这里；文件结构和内容不变。
- 存档文件名固定为 `handoff.md`，始终保存当前最新状态。
- 日期链路保存在文件开头的提示词中，每次更新只追加当前日期，不覆盖往期日期。
- 文件开头必须包含接替提示词，告诉下一段对话：
  - 当前在教什么
  - 用户的最终目标
  - 下一段对话接替任务
  - 任务目录绝对路径和当前日期，方便检索内容
  - 交接日期链，方便按日期检索往期对话内容
- 文件内容要尽量详细，最大限度保留模型对用户和当前任务的认知。

## 接替提示词模板

```markdown
> 我在教用户学习 <学习内容>，他的最终目标是 <最终目标>。
> 接下来由你接替我的任务，下面是该用户的状态信息和画像。
> 任务目录：<learning-tasks/<任务名> 绝对路径>
> 当前日期：<YYYY-MM-DD>
> 交接日期链：<YYYY-MM-DD> → <YYYY-MM-DD> → ...
> 往期对话可依据交接日期链，在 Codex 对应日期目录中检索。
```

## 更新时机

### 自动存档

- 用户每完成流程目录中的一项任务，自动更新一次 `handoff.md`。
- 每次更新在提示词的交接日期链中追加当前日期，保留往期日期。
- 更新后必须明确告诉用户存档已更新，例如：“已更新存档：learning-tasks/<任务名>/handoff.md”。

### 手动存档

- 用户输入 `/handoff` 时，立即执行交接更新。
- 同样更新最新状态，并在交接日期链中追加当前日期。
- 交接前确认关键状态都已写入，特别是当前进度、难点清单、待办和恢复点。

## 接续规则

- 新对话开始时，如果用户说“继续学习 <主题>”，优先在 `C:\Users\19935\Documents\Codex\learning-tasks\<任务名>\` 中查找 `handoff.md`。
- 读取文件后，先按接替提示词确认任务，再加载用户画像和当前进度，从恢复点继续。
- 如果需要查看往期内容，根据提示词中的交接日期链，在 Codex 对应日期目录中检索。
- 如果找不到文件，询问用户提供 `handoff.md` 的路径。
- 除非信息缺失或用户要求重新确认，否则不要重复完整的需求诊断。
